nanobanana-adc — Concept

コンセプト — ADC 対応 Gemini 3 Pro Image CLI

初版 2026-04-24（docs/seed.md）／ 現状反映 2026-08-16 ／ 対象バージョン v0.7.0 + Unreleased ／ 関連: tasks.md・CLAUDE.md・CHANGELOG.md
TL;DR：Google Nano Banana Pro（Gemini 3 Pro Image）の画像生成 CLI。唯一の差別化軸は ADC（Application Default Credentials）対応。既存の Claude Code image skill は例外なく GEMINI_API_KEY しか受け付けず、Vertex AI + ADC 構成の企業環境・CI/CD・Cloud Run が空白地帯になっている。そこだけを埋める。当初構想（v0）から実装は 3 点で拡張された —— doctor による診断、auth login による ADC セットアップ、PNG メタデータ埋め込み。いずれも「ADC 経路を実際に通せるようにする」ための追加であり、差別化軸そのものは動いていない。

1. 何を作るか

Google Nano Banana Pro（Gemini 3 Pro Image）を使った画像生成 CLI。唯一の差別化軸は ADC（Application Default Credentials）対応である。

既存の Claude Code skill（cc-nano-banana, ccskill-nanobanana, skill-nano-banana 等）はすべて GEMINI_API_KEY 環境変数のみ対応しており、Vertex AI + ADC 構成では使えない。企業環境・CI/CD・Cloud Run 等で Vertex AI を使うユーザーの空白地帯を埋める。

この軸を壊す変更は regression である。API キー経路はカジュアルユーザー向けのフォールバックにすぎず、ADC 経路の劣化と引き換えにしてよい機能は存在しない（CLAUDE.md 設計原則）。

2. 当初構想からの差分（v0 → v0.7.0）

初版 seed.md（2026-04-24）は「generate 一本の CLI」を想定していた。実装は以下の点で構想を超えている。差分はすべて ADC 経路の実用性に由来する。

項目当初構想現状（v0.7.0 + Unreleased）
サブコマンド generate のみ（暗黙） generate（既定）／ doctor（v0.4.0〜）／ auth login（v0.7.0〜）の 3 系統
既定モデル gemini-3-pro-image-preview gemini-3-pro-image（2026-05-28 に Vertex AI で GA）。preview alias も引き続き解決する
Vertex 呼び出し @google/generative-ai の GOOGLE_GENAI_USE_VERTEXAI=true モード Vertex 経路は 生 fetch、AI Studio 経路のみ SDK。location=global がリージョン接頭辞なしホストを要求するため SDK では表現できなかった（§6）
診断 （なし） doctor が env / ADC / quota project / gcloud config dir を診断。JSON schema nanobanana-adc-doctor/v1 として互換維持
ADC セットアップ ユーザーが gcloud を直接叩く前提 auth login が gcloud auth application-default login を CLOUDSDK_CONFIG 解決込みでラップ
出力 PNG を保存するだけ AIview 互換の parameters メタデータを PNG に埋め込む（--no-embed-metadata で無効化）
スコープ外 画像編集 / バッチ生成 / MCP サーバ化 変更なし。依然としてスコープ外（§9）

3. 配布形態

1 つのリポジトリで 2 通りの配布を兼ねる。コードベースを fork しない——同じ dist/cli.js・同じ bin/nanobanana-adc dispatcher を両方が使う。

用途方法
Claude Code plugin/plugin marketplace add hummer98/nanobanana-adc
スタンドアロン CLInpm install -g nanobanana-adc / npx nanobanana-adc
OpenCode 等の他 AI ツールnpm install -g 後にそのまま利用
Claude Code への隠れた結合を作らない。CLI は任意のシェルで単体動作しなければならない。plugin 配線（SessionStart フック・SKILL.md）は周縁に置き、src/ には CLAUDE_PLUGIN_ROOT 等の Claude Code 固有環境変数を持ち込まない。

6. CLI インターフェース

6-1. generate（既定サブコマンド）

# 基本（generate は省略可）
nanobanana-adc --prompt "a cat in space" --output cat.png

# サイズ・アスペクト比
nanobanana-adc --prompt "..." --aspect 16:9 --size 2K

# モデル指定（既定: gemini-3-pro-image）
nanobanana-adc --prompt "..." --model gemini-3.1-flash-image

# API キーを明示（既定は ADC）
nanobanana-adc --prompt "..." --api-key $GEMINI_API_KEY
オプション既定説明
-p, --prompt <text>（必須）プロンプト
-o, --output <path>output.png出力先パス
-a, --aspect <ratio>1:11:1 / 16:9 / 9:16 / 4:3 / 3:4 / 3:2 / 2:3 / 21:9 / 9:21 / 5:4
-s, --size <size>1K1K / 2K / 4K
-m, --model <id>gemini-3-pro-imageモデル id。allow-list は持たない（新モデルに追従できるように）
--api-key <key>—明示指定。認証優先順位の第 1 位（§8）
--person-generation <mode>—人物生成の制御
--no-embed-metadata埋め込むAIview 互換 parameters の埋め込みを無効化（PNG のみ）

6-2. doctor（v0.4.0〜）

環境・認証状態を診断する。モデル API は呼ばないので課金は発生せず、常に exit 0 を返す（スクリプトから安全に叩ける）。

nanobanana-adc doctor            # 人間向けテキスト
nanobanana-adc doctor --json     # 機械可読（schema: nanobanana-adc-doctor/v1）
nanobanana-adc doctor --verbose  # ACCESS_TOKEN 先頭 8 文字・gcloud raw・runtime
nanobanana-adc doctor --probe-metadata-server   # 169.254.169.254 を 300ms probe

診断項目は env 読取・ADC probe・quota project 照合・gcloud config dir 解決（$CLOUDSDK_CONFIG / $HOME/.config/gcloud）と、そこから計算される warning 群。JSON schema は nanobanana-adc-doctor/v1 として互換を維持する。

6-3. auth login（v0.7.0〜）

gcloud auth application-default login を CLOUDSDK_CONFIG のインライン解決と quota project 設定込みでラップする。ADC のパーミッション設定でつまずく（403）という DX 上の穴を埋めるためのコマンドで、doctor が報告する config dir / quota project と同じ解決規則に揃えてある。

nanobanana-adc auth login --dry-run          # 解決結果だけ出して exit 0
nanobanana-adc auth login --config-dir ./gcloud-ci --quota-project my-proj
オプション説明
--config-dir <path>CLOUDSDK_CONFIG を上書き
--quota-project <id>login 後に set-quota-project を実行
--no-quota-projectquota project 設定をスキップ
--scopes <csv>--scopes=<csv> を gcloud に渡す
--dry-run解決した実行計画を出して exit 0（gcloud を起動しない）
--verbose実際に渡す argv を表示

CLOUDSDK_CONFIG の解決順位：--config-dir → $CLOUDSDK_CONFIG（そのまま継承）→ $GOOGLE_APPLICATION_CREDENTIALS の dirname（basename が application_default_credentials.json のときのみ）→ gcloud の OS 既定（CLOUDSDK_CONFIG 未設定）。

quota project の解決順位：--quota-project → --no-quota-project（スキップ）→ $GOOGLE_CLOUD_PROJECT → スキップ + notice。

7. モデル

モデル id位置づけ
gemini-3-pro-image既定。Nano Banana Pro。2026-05-28 に Vertex AI で GA
gemini-3.1-flash-image高速・低コスト
gemini-3.1-flash-lite-imageさらに軽量
gemini-2.5-flash-image旧世代
gemini-3-pro-image-previewGA 前の preview alias。まだ解決するが GA id を推奨
location=global のリージョンレスホスト。Gemini 3 Pro Image は aiplatform.googleapis.com（リージョン接頭辞なし）からのみ提供される。src/generate.ts にはこの分岐が存在し、削除してはならない。通常の Vertex AI エンドポイント命名（<region>-aiplatform.googleapis.com）を素直に適用すると 404 になる。
--model に allow-list を持たせていないのは意図的である。新しい Gemini image モデル / リージョンが出たときに CLI 側のリリースを待たずに使えるようにするため。

8. 認証

8-1. 環境変数

変数必須説明
GOOGLE_CLOUD_PROJECTADC 使用時 ✓GCP プロジェクト ID
GOOGLE_CLOUD_LOCATIONADC 使用時 ✓リージョン（Gemini 3 Pro Image は global）
GOOGLE_GENAI_USE_VERTEXAIADC 使用時 ✓true 固定
GOOGLE_APPLICATION_CREDENTIALS任意ADC ファイルパス（未設定時は gcloud 認証を使用）
CLOUDSDK_CONFIG任意gcloud config dir 全体を OS 既定から隔離する
GEMINI_API_KEYフォールバックADC 未設定時に使用

8-2. 認証優先順位（src/auth.ts）

  1. --api-key <key> CLI フラグ
  2. GEMINI_API_KEY 環境変数
  3. ADC（GoogleAuth → access token）← 本命
この順序を入れ替えない。シェルに GEMINI_API_KEY を置いたまま --api-key を明示するユーザーは、明示した鍵が勝つことを期待している。

8-3. 認証の曖昧さでは黙らない

[auth] using: adc / [auth] using: api-key を常に出力する。コードを読まずにどちらの経路が発火したか判別できることが要件である。

9. Claude Code plugin 固有の設定

.claude-plugin/plugin.json に SessionStart フックを定義し、${CLAUDE_PLUGIN_DATA} に node_modules を展開したうえで ${CLAUDE_PLUGIN_ROOT}/node_modules から symlink を張る。これによりインストール後の初回セッションから依存なしで動作する。

{
  "hooks": {
    "SessionStart": [{
      "hooks": [
        { "type": "command",
          "command": "diff -q \"${CLAUDE_PLUGIN_ROOT}/package.json\" \"${CLAUDE_PLUGIN_DATA}/package.json\" >/dev/null 2>&1 || (... npm install --omit=dev ...)" },
        { "type": "command",
          "command": "[ -e \"${CLAUDE_PLUGIN_ROOT}/node_modules\" ] || ln -sfn \"${CLAUDE_PLUGIN_DATA}/node_modules\" \"${CLAUDE_PLUGIN_ROOT}/node_modules\"" }
      ]
    }]
  }
}

10. スコープ外（継続）

以下は初版から一貫してスコープ外である。別リポジトリまたは feature flag で検討する。

  • 画像編集モード（inpainting / outpainting）
  • バッチ生成（ファイルからプロンプトリストを読む）
  • MCP サーバーとしての配布

補足（issue #14, 2026-08-19）: --reference（参照画像入力）は 上記「画像編集モード」には含まれない。マスクを取って既存画像の一部を書き換える編集ではなく、 参照画像を条件として与える新規生成（キャラクター一貫性）であり、 generateContent の contents[].parts[] に inline_data を 足すだけで実現できる。inpainting / outpainting は引き続きスコープ外。
